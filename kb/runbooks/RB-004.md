# RB-004: Block reported that belongs to no file

## Symptom
The NameNode logs `addStoredBlock request received for blk_... on <dn> size <n> But it does not belong to any file.` when a DataNode reports a block the NameNode has no file for.

## Likely causes
- The file was deleted while a replica was still being written or reported.
- An abandoned write left an orphan block on a DataNode.
- A stale block report arrived after the file's blocks were invalidated.

## Checks
1. Look for `NameSystem.delete` lines that mention the same block close in time.
2. Check whether the writing job was cancelled or failed.
3. Confirm whether the block later appears in an invalidSet.

## Fix
The NameNode instructs the DataNode to delete the orphan replica. No manual action is needed unless the reports keep coming.

## Escalate
Escalate if orphan reports are numerous, since that can mean namespace metadata was lost.
