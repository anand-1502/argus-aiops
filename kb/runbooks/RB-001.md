# RB-001: Delete fails: BlockInfo not found in volumeMap

## Symptom
A DataNode logs `Unexpected error trying to delete block blk_... BlockInfo not found in volumeMap.` when it is told to delete a replica it has no record of.

## Likely causes
- The NameNode sent a duplicate or late delete (invalidate) command after the replica was already removed.
- The replica never finalized because the write failed part-way, so the DataNode has no volume map entry.
- The DataNode restarted and rebuilt its volume map without a replica the NameNode still lists.

## Checks
1. Search the DataNode log for an earlier `Deleting block` line for the same block id.
2. Check whether the block's write completed: look for `Received block ... of size` and `PacketResponder ... terminating`.
3. Compare the NameNode's invalidSet entries for this block against DataNode restarts in the same window.

## Fix
Usually harmless on its own: the NameNode retries deletes and the entry clears. If the same block id repeats for hours, restart the DataNode to rebuild its volume map and run a block report.

## Escalate
Escalate if many distinct blocks show the error at once, which points to a volume map corruption or a bad disk.
