# RB-003: Unplanned re-replication activity

## Symptom
NameNode lines `ask <dn> to replicate blk_... to datanode(s) <dn2>` followed by `Starting thread to transfer block` and `Transmitted block` show the cluster copying a block because it fell below its replication target.

## Likely causes
- A DataNode holding a replica went down or was decommissioned.
- A replica was corrupt or lost and had to be re-created.
- A write completed with fewer replicas than the target after a pipeline failure.

## Checks
1. Check which DataNode last held the block and whether it restarted recently.
2. Look for earlier write exceptions for the same block (see RB-002).
3. Check the replication queue size and whether transfers are keeping up.

## Fix
Let the replication monitor finish. If transfers are slow, raise the replication stream limits temporarily. Confirm the block returns to its target replication count.

## Escalate
Escalate if the same blocks are re-replicated repeatedly, which suggests an unstable node.
